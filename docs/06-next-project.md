# 06：独立项目、架构与发布

## 1. 把法兰实验扩展为自己的工具

课程已有尺寸输入对话框和参数验证。下一步按顺序扩展：

1. 左侧模型树，至少记录当前模型名称与参数。
2. 参数文件读写，保留 outer/thickness/bore/count/hole/pitch；加载后重建模型。
3. 撤销/重做：先保存参数快照，每次按快照重建。
4. 添加圆角参数，并在算法失败时保留上一份有效形状。
5. 添加装配信息时再学习 XDE，复杂文档与历史时研究 OCAF。

TopoDS_Shape 不会自动给你完整的草图约束系统或参数化历史。早期可以每次从参数完整重建，先保证行为清楚。

## 2. 推荐的应用边界

```text
UI：Qt 表单、按钮、错误提示
Document：参数、模型、单位、选中状态
Modeling：几何算法，返回结果或错误
Viewer：AIS、相机、显示、拾取
IO：CAD 文件、应用参数文件
```

本项目为了教学把 CadView 放在一个头文件中。扩大规模后可移入 .cpp，减少编译依赖，并拆出 Document 和 IO 服务。测试应继续调用 UI 使用的同一建模模块。

## 3. 性能和线程

目前按钮直接同步建模。复杂 STEP、布尔和网格化应交给工作线程；GUI 线程接收结果后更新 AIS。不要在工作线程里直接访问 QWidget 或同时修改同一个共享模型。

耗时任务需要进度、取消和错误恢复；线程退出前要确保模型和任务生命周期合理。不要为了看起来快就跳过合法性验证。

## 4. 可视化进阶

可继续研究材质、显示模式、透明度、剖切、测量标注、多个 View、AIS_ViewCube 和 AIS_Manipulator。要叠加 Qt 半透明控件时，学习 QOpenGLWidget 与 OCCT 的共享上下文/FBO 集成。

当前原生 QWidget 路线不承诺复杂混合合成。选择不同集成方式时应重新测试缩放、选择和生命周期。

## 5. 发布到另一台机器

Windows：用同一 Qt 安装的 windeployqt 处理 Qt DLL/插件，再检查 OCCT 和其 FreeType/TBB 等实际依赖。运行时资源按功能需要收齐，最后在没有开发环境的 Windows 上验证。

Mac：macdeployqt 处理 .app；用 otool -L 检查可执行文件和依赖是否还指向 `.local` 或其他开发机路径。补齐非 Qt 动态库与资源，最终再签名和按分发要求公证。

不要把整个 `.local` 或开发依赖上传 Git，当作最终安装包。当前仓库发布的是可复现学习源码，尚不宣称完成独立分发认证。

## 6. 六周学习安排

| 周 | 目标 | 交付 |
|---|---|---|
| 1 | 环境、C++/Qt、窗口 | 两个平台编译运行 |
| 2 | 几何拓扑、基本体、属性 | 基本体与体积记录 |
| 3 | 布尔、拉伸、回转、放样、圆角 | 完成模型实验 |
| 4 | 相机、拾取、DPI | 手工完成交互验收 |
| 5 | STEP/BREP/STL、错误恢复 | 完成文件往返与失败测试 |
| 6 | 参数、文档、撤销思路 | 独立法兰工具 |

然后阅读官方 Bottle 教程，继续曲线曲面、扫掠、装配和应用框架。使用 OCCT 7.9.3 离线文档与源码一起学习，在线 8.x 示例须先核对接口。
